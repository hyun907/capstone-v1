# 작업 컨벤션

이 문서는 개인 AI Agent 실습을 위한 규칙입니다. 기능이 추가되면 실제 코드와 검증 방법에 맞춰 갱신합니다.

## 코드 구조

| 위치 | 역할 |
| --- | --- |
| `mcp-server/` | MCP 도구, 입력·출력 스키마, 실습 데이터 |
| `backend/agent/` | LangGraph 상태, Supervisor 흐름, 외부 도구 연결 |
| `backend/schemas/` | API와 SSE 데이터 계약 |
| `backend/streaming/` | 에이전트 이벤트를 화면용 SSE로 변환 |
| `backend/eval/`, `backend/error_handling/`, `backend/perf/`, `backend/persistence/` | 평가, 오류 처리, 성능, 세션 저장 |
| `frontend/app/`, `frontend/components/`, `frontend/lib/` | 화면, 표현 컴포넌트, 통신·타입·상태 |

디렉터리는 해당 단계에서 필요할 때 만듭니다. 참조 자료의 완성된 구조를 미리 복사하지 않습니다.

## 코드 작성

- Python: 함수와 공개 데이터 경계에 타입을 적고, API 입출력은 Pydantic 모델로 정의합니다. 외부 연결은 가능한 한 주입하거나 별도 모듈로 분리합니다.
- TypeScript: 명시적인 이벤트 타입을 사용하고 `any`를 피합니다. 컴포넌트는 표현을, `lib/`는 통신과 상태 처리를 맡습니다.
- 이름은 역할이 드러나게 짓습니다. Python 파일·함수는 `snake_case`, 클래스와 React 컴포넌트는 `PascalCase`, TypeScript 변수·함수는 `camelCase`를 사용합니다.
- 주석은 복잡한 이유와 제약을 설명할 때만 씁니다. 단계 번호나 구현 예정 기능을 현재 동작처럼 적지 않습니다.
- 환경값과 모델 선택, 재시도 횟수는 코드 여러 곳에 흩어 놓지 않습니다. 비밀값은 환경 변수로 관리합니다.

## 에이전트·API 계약

- Graph 상태를 추가하거나 바꾸면 초기값, 분기, 종료 조건을 함께 확인합니다. 무한 재시도와 중복 도구 호출을 방지합니다.
- MCP 도구는 입력·출력과 실패 상황을 명확히 정의합니다. 실제 외부 시스템 없이 검증할 수 있는 대체 데이터는 실습용임을 표시합니다.
- SSE 이벤트 타입이나 필드를 바꾸면 백엔드 스키마, 변환기, 프런트엔드 타입과 표시 코드를 함께 수정합니다.
- `thread_id` 같은 세션 식별자는 요청부터 저장·응답까지 일관되게 전달합니다.
- 검증에는 정상 흐름뿐 아니라 빈 결과, 도구 오류, 연결 끊김 같은 관련 실패 흐름을 포함합니다.

## Git 작업

- `main`은 검증된 변경을 모으고, 작업은 `feat/`, `fix/`, `refactor/`, `docs/`, `chore/` 접두어가 붙은 짧은 브랜치에서 진행합니다.
- 이슈에는 목표와 완료 기준을, PR에는 변경 내용과 실제 검증 결과를 적습니다. 작업 범위가 작으면 한 PR에 한 기능이나 한 수정만 담습니다.
- 기능·실습 이슈 제목은 `[Feat] <짧은 한국어 설명>` 형식으로 씁니다. 기능 이슈에는 `enhancement` 라벨을 붙입니다.
- 이슈와 PR의 Assignees에는 `hyun907`을 지정합니다. PR을 만든 뒤에도 담당자가 표시되는지 확인합니다.
- 참조 자료에서 받은 코드·문서·설정 파일과 `.env` 등 비밀값은 공개 저장소에 커밋하지 않습니다. 공개 전에는 포함 파일의 출처와 공유 권한을 확인합니다.

### 커밋 제목

형식: `<이모지> <type>: <짧은 한국어 설명>` (이모지와 타입 사이 공백 한 칸, 제목 끝 마침표 없음)

| 이모지 | type | 용도 |
| --- | --- | --- |
| ✨ | `feat` | 새 기능 |
| 🐛 | `fix` | 버그 수정 |
| ♻️ | `refactor` | 동작을 유지하는 리팩터링 |
| 🎨 | `style` 또는 `chore` | 코드 형태·구조 개선 또는 프로젝트 설정 |
| ⚡️ | `perf` | 성능 개선 |
| 🔥 | `remove` | 코드·파일 삭제 |
| ✅ | `test` | 테스트 추가·수정 |
| 📝 | `docs` | 문서 추가·수정 |
| 🚀 | `deploy` | 배포 설정·작업 |
| 🔒️ | `security` | 보안 문제 수정 |

예: `🎨 chore: 프로젝트 세팅`, `✨ feat: Supervisor 라우팅 추가`, `🐛 fix: SSE 종료 이벤트 누락 수정`

한 커밋에는 한 목적만 담습니다. 테스트가 통과했다는 이유만으로 `✅test`를 쓰지 않고, 테스트 파일을 추가·수정했을 때 사용합니다. 필요하면 본문에 변경 이유와 검증 내용을 적습니다.
